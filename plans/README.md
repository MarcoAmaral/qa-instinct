### `install.ps1` ignores scope for `copilot` and `cline`

`install.sh` and `bin/cli.js` warn and skip when these two editors are installed with global
scope, because neither has a global target path. `install.ps1` never checks, so it writes the
project-scope path into the user's home directory instead. Found while extracting the shared
editor map (PR #63) and deliberately left unfixed there, since that change claimed no behaviour
difference. A second, smaller divergence sits beside it: one uninstall message says `Cursor`
where every other place says `Cursor / Trae`.

### The WSL Windows-profile install path has never been executed

Plan 010 item 7 fixed the manifest path recorded when installing from WSL into the Windows user
profile, but the fix was verified by reading it against `install.ps1` and by a guard test on
`install_file`. Actual `wslpath` behaviour, a real `$WIN_HOME`, and the antigravity global
target on that path have never run. Worth exercising end to end on a real WSL distribution
before trusting it.

### Spec-driven development integration (Spec Kit)

<https://github.com/github/spec-kit> produces specs, plans and tasks under `.specify/`. Three
candidate pieces of work, in value order:

1. **A spec-review command.** ISTQB static testing applied to a specification — acceptance
   criteria that cannot be tested as written, ambiguity, missing negative cases, states with no
   defined transition. Static testing is a CTFL v4.0 chapter with **no** coverage in this
   package today: `qa-review.md` is code review and `qa-refinement.md` is PM advisory. This is
   worth doing whether or not a repo uses Spec Kit.
2. **Detection in `.claude/rules/context-discovery.md`.** Where a spec exists, treat it as the
   authoritative requirements source rather than re-deriving requirements from a ticket. The
   rule's tier-3 "declared intent" list is where it belongs.
3. **A traceability command** — requirement to test case to result.

Do not hard-code Spec Kit's directory layout; it is young and has already moved. Follow the
detect-and-respect idiom of `.claude/rules/linting-standards.md` so the feature degrades
gracefully for the majority of repositories that will never adopt it.
